# Contributing to forge

Thanks for helping improve forge. This guide covers working on the **template repo
itself** — the scaffolder and the `template/` it renders. (Projects *generated* from forge
get their own contribution norms.)

> See [`AGENTS.md`](AGENTS.md) for the agent-facing version of these rules.

## Setup

```bash
git clone https://github.com/nuccig/forge.git
cd forge
npm install        # clack + nunjucks (the scaffolder's only deps)
```

Requires **Node ≥ 18**. No Python.

## How the repo is laid out

| Path | Role |
| --- | --- |
| `scripts/config.mjs` | Scaffold questions, derived vars, exclusion rules — the single config source. |
| `scripts/scaffold.mjs` | The TUI + non-interactive CLI (the `create-forge` bin). |
| `scripts/render.mjs` | Renders `template/` → target dir with Nunjucks (Jinja-compatible). |
| `template/` | What gets rendered into new projects. `*.jinja` = templated; everything else verbatim. |
| `template/.agents/skills/` | **Source of truth** for skills. Edit here only. |
| `template/.claude/`, `template/.github/` | Adapters generated by `sync-adapters.mjs`. Never hand-edit skill content here. |
| `docs/` | forge's own docs (not shipped into projects). |

## The golden rules

1. **No stack leakage.** Nothing in `template/` may name a language, framework, or vendor.
   Reference **tasks** (`just test`) and template variables (`{{ ... }}`).
2. **One source for skills.** Edit `template/.agents/skills/<skill>/SKILL.md`; the
   `.claude/` and `.github/` adapters are generated.
3. **One config source.** New scaffold variable? Add it to `scripts/config.mjs` *and* use
   it in `template/`.
4. **GitHub Actions in templates:** wrap `${{ … }}` in `{% raw %}…{% endraw %}` so Nunjucks
   doesn't try to render it.

## Develop & test

The "build" here is *render and verify*:

```bash
# Render with all defaults into a throwaway dir
node scripts/scaffold.mjs ./.render-test --defaults

# Override any prompt non-interactively (repeatable)
node scripts/scaffold.mjs ./.render-test --defaults --set task_runner=make --set include_sdd=false

# Hook unit tests (pure Node)
node .render-test/.claude/hooks/__tests__/run.mjs
```

Before opening a PR, sanity-check the render:

- `settings.json` is valid JSON; the workflow files are valid YAML.
- No unrendered `{% … %}` / `{{ … }}` leaked into output (except JS `${...}` and the
  intentional GHA `${{ }}`).
- If you touched adapter gating, render all four `primary_agent` values
  (`claude`, `codex`, `copilot`, `multi`) and confirm `.claude/` and the Copilot files
  appear only where expected.

Render dirs (`.render-*`, `.g-*`, `.nrt`) are gitignored.

## Commits & PRs

- [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`,
  `chore:`, `ci:` …).
- Update [`CHANGELOG.md`](CHANGELOG.md) under `[Unreleased]` for any change that affects
  generated output.
- Keep PRs focused; describe what a generated project looks like before/after.

## Releasing (maintainers)

Publishing to npm is automated by [`.github/workflows/release.yml`](.github/workflows/release.yml),
which fires on a `v*` tag.

**One-time setup:** create an npm **Automation** access token (npmjs.com → Access Tokens)
and add it as the repo secret `NPM_TOKEN`.

> Use an **Automation** token specifically — it bypasses 2FA. A "Publish"/"Granular"
> token still demands a one-time password on write, which a CI job can't supply
> (`npm error code EOTP`).

**Cut a release:**

```bash
# 1. Move CHANGELOG [Unreleased] items under the new version heading.
# 2. Bump + tag (choose patch | minor | major):
npm version patch
# 3. Push the commit and the tag:
git push --follow-tags
```

The workflow then verifies the tag matches `package.json`, runs `npm ci`, and publishes
`@nuccig/create-forge` with provenance and public access. Verify with:

```bash
npx @nuccig/create-forge my-app
```
